# forecast.json — 경로 탐색·대체 경로 추천용 데이터 명세

서울 지하철 **1~8호선** 혼잡도 예측 결과 + 노선 그래프. 이 파일 **하나만** 있으면
경로 탐색(Dijkstra)과 혼잡도 기반 대체 경로 추천을 구현할 수 있다.

- 파일: `output/forecast.json` (UTF-8, 단일 JSON 객체, 약 7.9 MB)
- 커버리지: 8개 호선 · **285 노드 / 279 간선**(환승역은 호선별로 분리) · 44,720셀
- 셀 = (호선 × 역 × 요일 8종 × 시각 5~24시)
- 그래프는 환승 간선까지 포함해 **단일 연결 요소**임을 검증했다(고립 노드 0).
- 생성: `python -m src.batch.export_forecast`
- 근거 데이터: 서울교통공사 OA-12921(시간대별 승하차) 2023–2025 요일별 평균,
  OA-12928(열차 혼잡도), 역사면적정보

## 2. 경로 그래프 (탐색에 필요한 최소 2개 키)

노드 식별자는 반드시 **`(호선, 역명)` 쌍**이다. 같은 역명이 여러 호선에 존재한다
(예: `종로3가`는 1·3·5호선). 역명만으로 노드를 잡으면 환승이 사라진다.

### `edges` — 같은 호선 내 인접 ★
```json
"edges": {
  "2": [["시청", "을지로입구", 1.5], ["을지로입구", "을지로3가", 1.0], ...,
        ["충정로", "시청", 1.5], ["성수", "용답", 3.0], ["신도림", "도림천", 1.5]],
  "5": [..., ["강동", "둔촌동", 1.83], ...]
}
```
`[역A, 역B, 소요분]`. **무방향**이며, 이 목록이 곧 인접 리스트다.
소요분이 `null`인 간선이 8개 있다(7호선 인천 연장·뚝섬유원지 — 역간거리 원자료에
없음). 이때는 `meta.min_per_station`(2.0분)으로 대체한다.

> **`lines` 배열의 index±1로 인접을 만들면 안 된다.** 아래 구조가 배열로는
> 표현되지 않는다. `edges`는 이 보정이 이미 반영된 결과다.
>
> | 호선 | 구조 | 배열만 쓸 때 생기는 오류 |
> |---|---|---|
> | 2 | 순환선 + 성수지선 + 신정지선 | 시청↔충정로 순환 폐합 누락, 지선이 분기점(성수·신도림) 대신 배열상 앞 역에 붙음 |
> | 5 | 마천지선 | 하남검단산↔둔촌동 가짜 간선, 강동↔둔촌동 누락 |
> | 6 | 응암순환 | 구산↔새절 가짜 간선, 구산↔응암·응암↔새절 누락 |

### `lines` — 역 목록·표시 순서
```json
"lines": { "1": ["서울역", "시청", ...], "2": ["시청", ..., "까치산"], ... }
```
노선도 표시나 역 목록에 쓴다. 인접 관계의 근거로 쓰지 말 것(위 표 참조).

### `segMin` — 역별 소요시간(참고용)
`segMin[line][station]` = 직전 역 → 이 역 이동 시간(분, 실측 평균).
`edges`의 가중치가 여기서 나왔으므로 **경로 탐색에는 `edges`만 있으면 된다.**
배열 순서와 실제 운행 순서가 다른 구간이 있어 이 표를 직접 이어 붙이면 안 된다.

### `xferMin` — 환승 가중치(분)
```json
"xferMin": {
  "종로3가": { "1-3": 1.63, "1-5": 4.33, "3-1": 1.63, "3-5": 1.63, "5-1": 4.33, "5-3": 1.63 },
  "충무로":   { "3-4": 0.23, "4-3": 0.23 }
}
```
키는 `"출발호선-도착호선"`이며 환승쌍마다 값이 다르다(종로3가 1↔5는 4.33분,
3↔5는 1.63분). 값이 없는 환승쌍은 `meta.transfer_min`(4.0분) 사용.

환승 간선은 **같은 역명을 가진 서로 다른 호선 노드 사이**에 만든다. 즉
`lines`를 훑어 `역명 → [호선,…]` 역인덱스를 만들고, 원소가 2개 이상인 역에
환승 간선을 건다.

> `xferMin` 항목 중 15개는 대응 노드가 없어 쓸 수 없다 — 9호선(8개)과
> 1호선 코레일 구간(7개: 신도림·창동·신길·도봉산·가산디지털단지·온수)이다.
> 이 데이터셋이 서울교통공사 운영 구간만 다루기 때문이며, 결손이 아니라 경계다.
> `lines`에 없는 호선 번호는 그래프에서 제외하면 된다.

## 3. 혼잡도 — `curve`

```json
"curve": {
  "2": {
    "강남": {
      "월": {
        "8": {
          "p": 0.0617,          // 승강장 밀도 (명/㎡)
          "pb": false,          // 승강장 배지: 평소 대비 1.6배 이상
          "pa": 6.8,            // 승강장 정원 대비 % (첨두 기준) ★주 지표
          "c": 0.0059,          // 대합실 밀도
          "cb": false,          // 대합실 배지
          "ca": 0.8,            // 대합실 정원 대비 %
          "level": "여유",       // 승강장 절대 4단계
          "level_c": "여유",     // 대합실 절대 4단계
          "badge_busier": false,   // pb && level이 주의/혼잡 → 경고 표시 조건
          "badge_busier_c": false
        },
        "9": { ... }
      },
      "화": { ... }, ..., "공휴일": { ... }
    }
  }
}
```

- 요일 키는 `days`의 8종. **공휴일은 별도 카테고리**(일요일과 상관 0.996, 평일의 0.52배).
- 시각 키는 문자열 `"5"` ~ `"24"`. 5시 이전은 데이터 없음.
- `pa`/`ca` (정원 대비 %)를 **대표 지표로 쓸 것**. 밀도 `p`/`c`는 원값이라 역 규모에 따라
  비교가 어렵고, `level`은 이미 `pa` 기준으로 계산돼 있다.
- 값이 `null`인 셀이 있다(면적 정보 없는 역). 반드시 null 체크.
- `curve`에 없는 노드가 **하나** 있다: 2호선 까치산(신정지선 종점). 승하차 원자료가
  이 역을 5호선으로만 집계한다. 경로 그래프에는 정상 포함돼 있으므로 통과·환승은
  되며, 혼잡도만 5호선 까치산 값을 참조하면 된다.

### 등급 경계
```json
"absBands": { "일반": [33.3, 66.7, 100.0], "휠체어": [16.7, 33.3, 50.0] }
```
`pa` 값을 이 경계로 잘라 여유/보통/주의/혼잡. **휠체어 이용자는 더 보수적인 경계**를 쓴다.
경계는 하드코딩하지 말고 이 필드를 읽을 것 — 상수 튜닝 시 값만 바뀌고 스키마는 유지된다.

### 시간 내 세부 형태 — `trainPct` (선택)
```json
"trainPct": { "2": { "강남": { "평일": { "480": 17.2, "510": 21.1, ... } } } }
```
키는 자정 기준 **분 단위 30분 슬롯**(480 = 8:00, 510 = 8:30), 값은 열차 재차율 %.
요일유형은 `평일`/`토요일`/`일요일` 3종(← `curve`의 8종과 다름).
시간 단위 `curve` 값을 30분 형태로 분해할 때 사용(총량 보존). 없으면 선형 보간.

## 4. 대체 경로 추천에 쓰는 방식

프로젝트 화면에서 실제로 쓰는 규칙이다. 참고 구현은 아래 코드 참조.

1. **경로 후보 생성** — 환승 페널티를 0 / 중간 / 높음으로 바꿔 Dijkstra를 여러 번 돌리고,
   특정 호선을 차단(`banLine`)해 우회 경로를 추가로 뽑아 중복 제거.
2. **경로 대표 혼잡도** = 도착역 단독이 아니라 **승차 지점(출발역 + 각 환승역)의 혼잡 최댓값**.
   실제로 사람이 몰려 못 타는 지점이 승차 지점이기 때문이다.
3. **각 지점의 시각**은 출발시각 + 누적 이동시간으로 계산하고, 시간 사이는 선형 보간(5분 단위).
4. **추천** = (소요시간, 대표 혼잡도, 환승 횟수)를 함께 제시하고 사용자가 선택.
   출발시각 ±1시간 범위로 흔들어 더 한산한 출발시각도 함께 제안.

### 참고 구현
| 파일 | 함수 | 내용 |
|---|---|---|
| `src/web/app.js:144` | `adjacency()` | `edges` → 인접 리스트 (**여기부터 보면 된다**) |
| `src/web/app.js:161` | `route()` | Dijkstra (JS, forecast.json 직접 사용) |
| `src/web/app.js:195` | `routeOptions()` | **대체 경로 후보 생성** |
| `src/web/app.js:279` | `repMetric()` | 경로 대표 혼잡도 |
| `src/serving/service.py:134` | `route()` | Dijkstra (Python) |
| `src/serving/service.py:201` | `journey()` | 경로 각 구간의 도착 시점 혼잡 |
| `src/serving/service.py:216` | `recommend_departure()` | ±1시간 출발시각 추천 |

그래프 생성 쪽은 `src/loading/loaders.py`의 `load_line_order()`(216)와
`load_line_edges()`(282), 보정 표 `LINE_EDGE_FIXES`(263)를 보면 된다.

## 5. 한계 — 받는 쪽에서 알아야 할 것

- **서울교통공사 운영 구간만.** 9호선·수인분당선·신분당선, 1호선 코레일 구간
  (구로·창동·의정부 방면 등)은 없다. 1호선은 서울역~청량리 10역뿐이다.
  따라서 이 데이터만으로는 **서울 전역 경로 탐색이 되지 않는다** — 예를 들어
  신도림(1호선)·창동(1호선) 환승이 빠져 일부 경로가 실제보다 길게 나온다.
  전역 서비스를 하려면 코레일·9호선 데이터셋을 추가로 붙여야 한다.
- **응암순환(6호선)은 실제로 단방향**이나 여기서는 무방향 간선으로 뒀다.
  역촌~구산 구간을 역방향으로 가는 경로가 실제보다 짧게 계산될 수 있다.
- 급행 열차는 모델링돼 있지 않다(9호선·1호선 급행 등 애초에 대상 밖).
- **캘린더 기반 예측이다.** 요일·시간·월만 사용하며 실시간 승하차·날씨·행사는 반영되지 않는다.
  검증 결과 seasonal-naive 대비 개선폭은 MAE 3~13% (`output/prediction_metrics.md`).
- **`causes`는 데모 샘플 3건**이다. 실제 공사·사고 정보가 아니므로 그대로 노출하면 안 된다.
- **역간 소요시간은 정차시간 포함 실측 평균**이며, 급행·완행을 구분하지 않는다.
- 환승 인원은 OA-12033을 시간 분배해 근사한 값이다(호선 수 균등 분할 가정).
- `absMeta.crush`(승강장 1.5명/㎡, 대합실 1.0명/㎡)는 면적 평균 기준 가정값이다.
